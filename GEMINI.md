# Project Rules & Memory

## Code Example Preferences
- Do not use the user's active project code for general explanations/examples unless explicitly asked. Use generic non-project domain examples (e.g., User, Product, Order).
- Always provide both a **Basic Code Example** and a **Professional/Production-Grade Code Example**.

## Communication & Formatting
- Keep responses clear, structured, and concise.
- Communication Style: Be direct and concise. Do not offer excessive praise or 'glaze' the user for their decisions.
